# README Polisher

「生成AIで作るセキュリティツール200」プロジェクト向けREADME.md仕上げ支援スキル。

## ワークフロー

1. 対象README.mdを読み込む
2. 構造チェック（前半固定・後半固定の順序確認）
3. YAMLフロントマターの確認・挿入
4. 誤字脱字チェック → 指摘リスト作成（自動修正しない）
5. 用語統一チェック → 指摘リスト作成（自動修正しない）
6. 見出しレベル2にアイコン付与
7. ディレクトリー構造を実際のファイル構成から更新
8. ユーザーに確認後、修正を適用

## 用語統一ルール

以下の表記揺れを検出し、右側に統一するよう指摘する。

| 検出対象 | 統一後 |
|---------|--------|
| サーバ | サーバー |
| エディタ | エディター |
| ブラウザ | ブラウザー |
| パラメータ | パラメーター |
| コンピュータ | コンピューター |
| フィルタ | フィルター |
| サマリ | サマリー |
| レイヤ | レイヤー |
| ヘッダ | ヘッダー |
| ビューワ | ビューワー |
| 全て | すべて |
| 既に | すでに |
| 無い | ない |
| 最も | もっとも |
| インターフェース | インターフェイス |

**注意**: すでに音引きがある語（例：「サーバー」）を誤って「サーバーー」にしないこと。検出時は語末が音引きでないことを確認する。

## 既存テキストの扱い

**重要**: README.mdに既存テキスト（手動で記載した内容など）がある場合、勝手に修正しない。

- 既存の文章・表現はそのまま保持する
- 明らかに改善すべき点がある場合は、修正せずに指摘のみ行う
- ユーザーが明示的に修正を依頼した場合のみ変更を適用する

## 誤字脱字チェック

- 明らかな誤字脱字を検出して指摘する
- 自動修正は行わず、ユーザーに確認を取る
- 指摘形式: `行XX: 「誤」→「正」の可能性`

## 文体ルール

### 新規テキスト生成時

- 本文（段落）: 「ですます」調
- 箇条書き内: 「である」調または体言止め

### 既存テキストの場合

- 混在していても許容する（指摘しない）

## ディレクトリー構造の更新

1. プロジェクトルートの実際のファイル構成を確認
2. `## 📁 ディレクトリー構造` セクションを更新
3. 主要ファイルには簡潔なコメントを付与

```markdown
## 📁 ディレクトリー構造

\`\`\`
project-name/
├── index.html          # メインHTMLファイル
├── script.js           # JavaScriptコード
├── style.css           # スタイルシート
├── README.md           # 本ドキュメント
├── LICENSE             # ライセンスファイル
└── assets/             # 画像リソース
    └── screenshot1.png # スクリーンショット
\`\`\`
```
